# Console access
- Validate console identity server-side with requirePropertyAdmin for hostel operations and requireSuperAdmin for cross-property settings, restaurant controls and payment activation; never infer authorization from navigation or browser storage.
- Keep booking records property-tagged and enforce matching property RLS on their child rows and invoices; the hostel operator must not access another property's records, even through direct API calls.

- Preserve existing console URLs and carry the selected property in validated search state; generate property-specific check-in QR URLs from the shared canonical-domain helper, and use shared catalogue/meal facts for console summaries so public content remains unchanged.
- Property setup (Booking Config → Property tab at `/admin/booking-engine`; `/admin/property` redirects there; `src/property/`) is the single store for property type, location, amenities, listing presence and hidden room types; location is a Google Maps link the admin pastes once (pin read from the link text) and guests are redirected to it; no Google Maps API calls or embeds, so there are no Maps charges. /book reads it through the public read-only server function; listing logos are never links.
- Console access comes from `be_property_staff` (read via `be_my_console_access`), not email allowlists: super admin is admin@xtsy.one; a hostel `property_admin` gets hostel operations only; Team & logins and Connections are super-admin only (nav and server); `front_desk` gets only `/admin/check-in` (DESK_PATHS) for its own property, gated by the property's `desk_logins_enabled`. Logins are created and changed only through `team.functions.ts` with the service role, so staff cannot grant themselves access.
- Property admins are limited to XTSY Travellers Hostel (`canManageMember`) because hostel-scoped handlers (`assertPropertyScope`) assume it; extend that before allowing admins for other properties.
- Today shows operations only; smart pricing lives at `/admin/pricing` and enquiries in `/admin/inbox`. Occupancy counts only properties with live inventory and labels the campsite as not tracked.
- Search trend charts use the same place classifier as pricing and store daily values with query details in the existing snapshot JSON; decode legacy query arrays without invented history, refresh only on admin action, and never equate site impressions with all Google searches.
- Blocks live in Inventory → Bulk edit (`?view=bulk`, `InventoryBulk`); `/admin/stays` only redirects there so old links and sheet-pairing instructions keep working.
- Console date filters share `src/admin/dateRange.ts` and `DateRangeBar` (?range=&from=&to= on the console layout search); day-wise lists use `groupByDay`, and Today insights come from the pure `summarizeArrivals` so ranges behave the same on every page.
- Sales (`/admin/inbox`, labelled Sales) owns enquiries, offline payment records (`be_sales_payments`) and invoices for WhatsApp bookings (`be_sales_invoices`, folio snapshot frozen at issue, numbered from the shared `be_next_invoice_seq` business-invoice series); rules live in pure `src/admin/sales.ts`. Online /book bookings keep the separate `be_invoices` ledger.
