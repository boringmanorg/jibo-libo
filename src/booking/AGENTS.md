- Smart pricing (`src/booking/smartPricing.ts`, `be_smart_pricing`) is owner-authorised automatic pricing: off per room type until the super admin switches it on, always clamped to the owner's lowest/highest, applied through `rateFor` in both the live engine and the enquiry-mode quote so displayed and charged amounts match.
- Search demand (`src/booking/demandIntent.ts`, `be_demand_snapshots`) classifies Google search appearances by place (Shillong/New Shillong → hostel, Dawki/Shnongpdeng → camp, other places ignored), stays neutral below MIN_RECENT, and is read only when the super admin presses refresh; `loadPricing` applies the hostel's reading (≤14 days old) as `demandMultiplier`, still clamped to owner limits. Camp readings are advice only.
- Manual night prices (`be_rate_overrides`, super admin, set from Inventory) reach guests through `loadPricing` as `SmartRule.overrides` and apply only while that room type's smart pricing is off; the server refuses to save them while it is on, so the two never mix.
- GST-registered properties issue Sales tax invoices (TI series): folio line amounts stay GST-inclusive and are split by `gstBreakdown` into taxable/CGST/SGST (intra-state), so turning GST on never changes a guest's total.

- OTA bookings hold their rooms on /book as synthetic block rows (`otaHolds`) until the sheet counts them: with write-back on (`sheet_write` set) the hold ends only when the sheet's script has written the booking ('applied'); without it, when the owner edits that night (counts at arrival in `sheet_at_arrival`). An opening saved after them or a cancellation also ends it.
- Google Sheet write-back goes only through the queue in `src/booking/sheetWrites.server.ts` (`be_sheet_writes`): the website never calls Google; the paired sheet's script collects requests with its token, writes them (lowest-numbered room fitting the whole group, split only if none fits; "Name 2B MMT" for dorm beds, "Name 2G XTSY" for private-room guests; never below 0) and acknowledges them with the counts that include them. Publish the counts first, then mark the requests applied, so a booking is never counted twice as free. Nothing is queued until `writeBackGate` passes (ZimmerStack live for the hostel with all rooms mapped, PMS switched on with its endpoint, Zoho Payments configured, sheet running the script); website bookings are queued only after a successful payment. Website bookings stop being subtracted (`loadLoads`, `websiteLoads`) only once `sheet_write` is 'applied'.
- /book HTML and server-function responses are `no-store`; returning to a booking tab or a back-forward restore re-runs loaders, so returning visitors never see stored counts.
- /book's server render does not wait for the database: its loader returns `BOOK_PAGE_PENDING` during SSR and the page fetches the live counts in the browser, showing room placeholders (never rooms) until they arrive.
- Guests manage a booking at /book/manage only through `src/booking/manageBooking.server.ts`: reference + booked phone (last 10 digits) every time, failed tries throttled per visitor and per booking (`be_guest_lookups`, hashed visitor, no phone stored), one answer for every mismatch. Balance payments reuse an open link for the same amount and are settled by `settleLink` (webhook or page view). A date change is only a request (`be_change_requests`, one open per booking); the desk applies it with the console's own date-change action.
- When nothing is free, search results carry `suggestions` from `nearestOpenStays` (same nights, up to 7 days earlier / 14 later, closest first) in both the live engine and the enquiry-mode search.
- An OTA reservation re-sent under a new ZimmerStack id is kept with `duplicate_of` (same OTA name and code): the same stay holds and is written to the sheet once; a different stay holds too and is flagged in the console.
- Hostel POS (posbyxtsy.club) pulls `GET /api/public/pms-feed` on each sync (`src/booking/pmsFeed.ts`, `pmsFeed()` in publicEngine.core): room types with their beds/rooms (floor labels, else spread over the sheet's room numbers) and the free count per night for 120 nights, worked out exactly as /book does. Public data only, read-only, CORS open, never cached. Engine ids stay the room-type ids end to end (website → PMS → ZimmerStack); renaming an id breaks the PMS link.
- Each property's rooms, rates and meals live in its own file under src/properties/ and are reached through the registry in src/properties/index.ts (unknown ids get an empty catalogue); console code looks properties up there instead of branching on ids, so editing one property cannot change another.
